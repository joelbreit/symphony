# Adding a composition to the listening room

Instructions for composers (human or agent) packaging a piece for the web
player in `web/`. The player is fully data-driven: drop a piece package into
`web/public/pieces/<your-id>/`, register it in the index, and it appears in
the gallery with the full experience — piano roll, constellation seek bar,
section narration, instrument spotlighting.

**The Window** (`web/public/pieces/the-window/`) is the reference piece; when
in doubt, imitate it.

## What I need from you

Minimum: **one MIDI file per movement** (a single-movement piece is fine) and
**rendered audio of those exact MIDI files**. Everything else is optional —
but the optional fields are where your piece gets its voice, so read
"Expressive fields" below before deciding to skip them.

## Package layout

```
web/public/pieces/<piece-id>/
  piece.json          # the manifest (schema below)
  notes/mvt1.json …   # note data per movement (generated, don't write by hand)
  audio/mvt1.m4a …    # rendered audio per movement
web/public/pieces/index.json   # gallery index (regenerated by the tools)
```

`<piece-id>` is a URL-safe slug (`my-piece`). It becomes the share URL:
`…#/my-piece`.

## Step 1 — convert the MIDI

```sh
.venv/bin/python tools/midi_to_piece.py \
    --id my-piece --title "My Piece" --composer "Your Name" \
    path/to/mvt1.mid path/to/mvt2.mid     # one file per movement, in order
```

This writes the note JSON, a **skeleton piece.json**, and rebuilds the index.
Re-running it later regenerates the note data but **preserves your hand-edited
manifest** (it only refreshes measured fields like durations). Use `--force`
to start the manifest over.

Check the converter's guesses afterwards: instrument display names come from
MIDI track names, families from GM program numbers. Fix anything wrong
directly in `piece.json`.

## Step 2 — render the audio

Render **from the same MIDI files you converted** — visual/audio sync depends
on both deriving from the same tempo map. Any GM soundfont works; The Window
used GeneralUser GS (github.com/mrbumpy409/GeneralUser-GS).

```sh
fluidsynth -ni -g 0.5 -r 44100 -F /tmp/m.wav <soundfont>.sf2 mvt1.mid
afconvert -f m4af -d aac -b 160000 /tmp/m.wav \
    web/public/pieces/my-piece/audio/mvt1.m4a    # macOS; elsewhere use ffmpeg:
# ffmpeg -i /tmp/m.wav -c:a aac -b:a 160k …/audio/mvt1.m4a
```

Watch fluidsynth's output for clipping warnings; lower `-g` if needed. If the
render has a long reverb tail, the manifest `duration` (which the converter
estimates as last-note-end + 1.5s) may need a small bump to match.

## Step 3 — fill in the manifest

`piece.json`, full schema. Required fields marked •.

```jsonc
{
  "schema": 1,
  "id": "my-piece",                    // • matches the directory name
  "title": "My Piece",                 // •
  "subtitle": "for chamber orchestra",
  "composer": "Your Name",             // •
  "year": 2026,
  "concept": "one sentence that earns the play-press.",
  "about": ["paragraph…", "paragraph…"],          // the About panel
  "credits": [{"label": "Rendering", "value": "FluidSynth + GeneralUser GS"}],
  "theme": {
    "accent": "#d9a84e",                          // colors buttons, playhead, labels
    "instrumentColors": {"violin-i": "#ffd27a"}   // optional per-instrument override
  },
  "instruments": [                     // • order defines the note-data indices
    {"id": "violin-i", "name": "Violin I", "family": "strings"}
    // family ∈ strings|winds|brass|color|voices|keys|other — drives the
    // default palette (members of a family get successive shades)
  ],
  "movements": [{                      // •
    "id": "mvt1", "num": "I", "title": "…",
    "key": "C minor", "tempoLabel": "Allegro",
    "note": "one-line program note shown in the About panel",
    "duration": 338.5,                 // seconds, should cover the audio length
    "audio": "audio/mvt1.m4a", "notes": "notes/mvt1.json",
    "sections": [[0, "label"], [64.2, "another label"]]   // seconds, sorted
  }],
  "emblem": {                          // optional: a motif on a small staff
    "label": "the Question",
    "states": [
      {"notes": [{"p": "G4"}, {"p": "Eb5"}], "mark": "?"},
      {"notes": [{"p": "G4"}, {"p": "E5"}, {"p": "C5", "accent": true}],
       "trigger": {"movement": "mvt4", "time": 160.0}}    // switches from here
    ]
  },
  "moments": [{                        // optional: timestamped annotations
    "movement": "mvt1", "time": 60.1,
    "text": "four notes fuse — it will not resolve for eighteen minutes.",
    "spotlight": "trumpets",           // instrument id to auto-highlight
    "hold": 10                         // seconds on screen (default 8)
  }]
}
```

Notes on mechanics:

- **Note data format** (generated): each `notes/*.json` is a flat array of
  `[startSec, durationSec, midiPitch, instrumentIndex, velocity]`, sorted by
  start. `instrumentIndex` points into the manifest's `instruments` array.
- **Deep links**: `…#/my-piece?m=mvt2&t=84` opens movement 2 at 1:24, paused.
  Use these to share your moments.
- The pitch range of the roll auto-fits your piece; nothing to configure.

## Expressive fields — the quality bar

The player is dark and quiet; your words appear in it like titles in a film.
Write accordingly.

- **`concept`** — one sentence, lowercase works well, no marketing voice.
  It's the only thing a visitor reads before deciding whether to press play.
- **`sections`** — chapter titles, not analysis. "the storm returns", not
  "Recapitulation (mm. 117–164)". Aim for one every 20–60 seconds; they are
  the sound-off narration.
- **`moments`** — your two or three best "listen for this" instants, with a
  spotlight if one instrument carries the event. Don't exceed ~1 per minute;
  they should feel rare.
- **`accent` color** — pick something that *is* the piece. The Window is
  candle-gold; a nocturne might be moonlight-silver (#aebfd9), a dance
  something hot. All UI chrome follows it.
- **`emblem`** — only if your piece genuinely has a motif. 3–6 notes,
  pitches roughly G3–C6 fit the staff best. A `trigger` lets it transform
  when the music does.
- **`about`** — program notes, 2–4 short paragraphs, first person welcome.

## Step 4 — verify

```sh
cd web && npm run dev
```

Checklist:

- [ ] Piece appears in the gallery (`#/`) with title, concept, accent color.
- [ ] Overview constellation looks right; press play — audio and the lit
      notes at the playhead must align (if they drift, the audio wasn't
      rendered from the converted MIDI).
- [ ] Movement pills, seeking on the constellation strip, and auto-advance work.
- [ ] Section labels and moments appear when expected.
- [ ] Check a phone-sized window (~375px): legend scrolls, labels readable.
- [ ] Console clean.

Then `npm run build` and ship `web/dist/`.
