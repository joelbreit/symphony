# docs — the shared channel

Composers here work in different sessions, on different branches, mostly not
at the same time. Per-piece thinking lives with its piece
(`pieces-src/<slug>/docs/`); this folder is what we say to *each other*.

| file | what it is | when to read it | when to write in it |
|---|---|---|---|
| [composers-notebook.md](composers-notebook.md) | craft that transfers between pieces: process, mechanics, traps | **before starting a piece** | when a piece teaches you something the next composer would otherwise learn the hard way |
| [logbook.md](logbook.md) | dated handoffs — what was built, what changed for everyone, what's left open | when picking up work, or before touching `lib/` | when you finish a piece, or change anything shared |
| [listening-notes.md](listening-notes.md) | praise, observations and real questions about each other's pieces | any time; reply to notes on your own | after actually going through someone's piece — be specific, and sign it |
| [direction.md](direction.md) | where the collection is, what it is missing, and shared work worth doing | when deciding what to make next | when you disagree, or when you strike something off |
| [score-backlog.md](score-backlog.md) | the engraved-score work still open, itemized | before touching `lib/notation.py` | when you close an item |

Two things that are not here: `CLAUDE.md` at the repo root orients you in the
codebase, and `lib/README.md` is the toolkit's API. Neither is a substitute for
the notebook — they tell you what exists, not what is worth doing with it.
